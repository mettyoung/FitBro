# Ralph Progress Log — recent-meals

## Codebase Patterns
- **Repo layer**: `FoodDiaryRepository` (interface) + `FoodDiaryRepositoryImpl` (SQLDelight). Flows via `database.foodDiaryQueries.<q>().asFlow().mapToList(Dispatchers.Default).map{...}`. Suspend writes via `withContext(Dispatchers.Default){ ... transactionWithResult{} }`.
- **SQLDelight queries**: `composeApp/src/commonMain/sqldelight/com/mettyoung/fitbro/data/db/FoodDiary.sq`. `LIMIT ?` → bind param is `Long`. Single table `FoodDiaryEntry`; no migrations for this feature.
- **Row→domain**: private `FoodDiaryEntry.toDomain()` extension at bottom of Impl maps `food_id`→`foodId`. Detached template = `.copy(id = 0, sortOrder = 0)`.
- **Model**: `data/model/FoodDiaryEntry.kt` — `id: Long=0`, `sortOrder: Long=0`, `brandName/foodId` nullable. `MealType.{BREAKFAST,LUNCH,DINNER,SNACKS}`, `MealType.ordered`. `ServingUnit.GRAMS="g"`.
- **commonTest**: NO SQLDelight driver, NO coroutines-test. `FoodDiaryReorderTest.kt` has its OWN private `FakeFoodDiaryRepository` + private `runSync` (StateFlow emits sync, no real suspension). When adding a repo method, MUST add it to that fake or tests won't compile. Read flows once via `.first()`.
- **sortOrder contract**: addEntry → maxSortOrderForDateMeal+1; getEntriesForDate orders by (mealType, sortOrder, id).
