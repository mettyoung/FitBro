## Codebase Patterns
- multiplatform-settings 1.3.0: Android actual uses `SharedPreferencesSettings(prefs)` from `com.russhwolf.settings.SharedPreferencesSettings`; iOS actual uses `NSUserDefaultsSettings(NSUserDefaults.standardUserDefaults)` from `com.russhwolf.settings.NSUserDefaultsSettings`. Both in same artifact `com.russhwolf:multiplatform-settings` added to commonMain.
- Cache keys follow pattern `{type}_{startDate}_{endDate}` for date-range lookups; sync timestamps use `sync_{CacheSource.name}` as keys.

- K/N 2.3.21 ObjC category methods need EXPLICIT imports to be accessible on class companions — e.g. `import platform.HealthKit.kilocalorieUnit` for `HKUnit.kilocalorieUnit()`, `import platform.HealthKit.predicateForSamplesWithStartDate` for `HKQuery.predicateForSamplesWithStartDate(...)`, `import platform.Foundation.localTimeZone` for `NSTimeZone.localTimeZone`. Direct-on-interface methods (like `HKHealthStore.isHealthDataAvailable()`) work without extra import.
- Use `NSCalendar(calendarIdentifier = NSCalendarIdentifierGregorian)` — `NSCalendar.currentCalendar` and `NSCalendar.current` are NOT accessible in K/N 2.3.21 (category methods, same issue)
- Health data package: `com.mettyoung.fitbro.data.health` for HealthKit/HealthConnect; `HealthResult<T>` + `HealthDataError` mirror `ApiResult<T>` + `CronometerApiError` pattern
- Auth files (OAuthRepository, TokenStorage, PkceGenerator) were pre-scaffolded as untracked files; check git status before writing new files to avoid duplicates
- iOS cinterop: never use `is CFStringRef` (erased type) in when expressions — use `is CPointer<*>` instead
- iOS TokenStorage casts NSMutableDictionary → CFDictionaryRef with @Suppress("UNCHECKED_CAST"); warnings are expected and benign
- PkceGenerator.ios.kt uses CoreCrypto CC_SHA256 + posix gettimeofday for time — no Foundation dependency needed
- TokenStorage.android.kt requires AndroidAppContext singleton initialized in FitBroApp.onCreate()
- OAuthCallbackHandler uses SharedFlow with extraBufferCapacity=1 for delivering redirect URI callbacks to coroutine consumers
- Gradle typecheck: use :composeApp:compileDebugKotlinAndroid (Android) and :composeApp:compileKotlinIosSimulatorArm64 (iOS) — compileKotlinAndroid is ambiguous
- Data layer package: `com.mettyoung.fitbro.data.model` for domain models, `com.mettyoung.fitbro.data.cronometer` for Cronometer API client code
- Ktor HTTP client pattern: each service creates its own HttpClient instance (same as OAuthRepository); use `parameter()` for query params, `header()` for auth header
- CronometerOAuthConfig.API_BASE_URL = "https://cronometer.com/api" — add new endpoints as `${API_BASE_URL}/endpoint/`
- ApiResult<T> (Success/Failure) mirrors OAuthResult pattern — use for all data layer results; CronometerApiError covers NetworkError, HttpError, RateLimited, Unauthorized, ParseError
- OAuthRepository.getValidToken() handles token refresh automatically; data sources just call it and unwrap Success or return Unauthorized failure
- `currentEpochMs()` expect/actual in `com.mettyoung.fitbro.util` — use for all timestamp needs in common; iOS actual needs `import platform.Foundation.timeIntervalSince1970`
- UI state holders live in `com.mettyoung.fitbro.ui.{feature}`; take CoroutineScope as constructor param (caller owns scope lifecycle)
